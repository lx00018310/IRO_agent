## 使用流程

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m iro_agent.cli setup
```

或双击 `start_iro_agent.bat`。未完成配置时启动菜单会自动进入向导。

向导分为项目工作目录、来源管理、模型/可选飞书、校验保存四步。来源管理可重复添加、查看或删除；每类都允许多个来源，至少保留一个来源。工作目录存放项目认知缓存，可以与主代码目录不同。数据库密码可用环境变量或隐蔽输入；HTTP 鉴权只保存请求头环境变量名。

完成后可执行：

```powershell
# 查看全部来源
.\.venv\Scripts\python.exe -m iro_agent.cli sources

# 只读连通性检查：目录 / PostgreSQL SELECT 1 / HTTP GET
.\.venv\Scripts\python.exe -m iro_agent.cli sources --check

# 无需模型凭据的静态认知构建
.\.venv\Scripts\python.exe -m iro_agent.cli init --static-only

# 配置有效模型凭据后启动对话
.\.venv\Scripts\python.exe -m iro_agent.cli chat
```

追加或删除来源时重新运行 `setup`。原配置会保留并导入；取消、中断或保存失败不会覆盖原文件。来源校验失败时，必须明确选择保留不可用来源才会保存；后续读取会报告观测缺口。

配置默认来自当前目录 `config.json`，可通过 `IRO_CONFIG_PATH` 或命令前的 `--config` 指定。不会自动读取示例文件或其他安装目录的旧项目。`init`、`chat`、`investigate`、`gateway start`、`eval` 在未完成配置时返回非零退出码。直接修改项目身份、来源位置、用途或名单会使完成标记失效；密码和环境变量凭据值可独立轮换。

普通问答与故障调查使用同一来源适配层。省略 `source_id` 时分别读取同类全部来源；指定 ID 时只读取该来源。部分失败会保留其他来源结果并标注失败项，故障调查将其视为观测缺口，可再指定可用来源核实。

## 整体 Review 发现与修复

| 问题 | 修复结果 |
| --- | --- |
| 单一代码根目录、单一数据库使多源配置无法实际使用 | 统一 SourceReaders 接通普通问答、调查工具与来源清单；知识扫描覆盖所有登记代码及数据库来源 |
| 默认 TASK-013 路径、业务数据库及示例文件可能带入新环境 | 新配置默认为空；缺配置必须完成向导；示例 JSON 原有非法占位数值已修正 |
| 只显示配置提示仍可能进入业务入口 | CLI 统一阻断业务命令；新配置的 RuntimeDispatcher 也执行完成检查；Windows 入口自动引导 |
| 同名文件、实体、表与业务 source_id 字段可能混淆 | 结果及表知识保留来源 ID，代码图实体 ID 按来源隔离；业务记录自身的 source_id 不会被覆盖 |
| 一个大来源可能占满模型上下文、掩盖后续来源或失败 | 按来源保留有界数据摘要；每个来源的 ID、状态及失败信息进入普通模型与调查规划器上下文 |
| 追加来源后可能复用旧蓝图 | 认知缓存绑定项目与来源配置指纹；变化后停止使用旧蓝图，`init` 重建 |
| 绝对路径中的 test 字样让正常源码被跳过 | 排除规则以来源内相对路径判定；多个来源的实际精读已验证 |
| 多目录下文件穿越或符号链接可能越出所选来源 | 代码读取、静态扫描、配置扫描和深读检查解析后的来源范围 |
| 凭据可能出现在多源列表、异常或摘要中 | 列表不提供凭据值；递归掩码来源列表内密码；源凭据参与结果、异常和审计脱敏 |
| 向导取消、文件并发修改及 Windows 脚本退出码可能造成误保存或假成功 | 原子保存、保存前并发检查；取消不覆盖；Windows 脚本保留命令退出码 |
| CLI eval 被误当成完全离线维护入口 | 代码检查确认其可能使用真实读取器，因此也要求完成配置，未增加绕过参数 |
| 工作目录丢失时可能改用其他目录的项目缓存 | 业务入口阻断并要求恢复工作目录或重跑向导 |

## 使用边界

- 数据库沿用 PostgreSQL。多个数据库分别执行 SQL，保留来源；不支持跨库 SQL JOIN。
- HTTP 只允许登记的精确 GET 端点，不跟随重定向，不启用浏览器或提交登录表单。动态查询地址需要分别登记。
- 版本工具仍以第一个代码来源为源码版本源，另保留可选 WRelease；多源代码检索和静态扫描不受此限制。
- 静态认知无需模型 Key；在线问答、调查和深度模型认知仍需要有效凭据。
- 新增验证使用临时目录、本机 HTTP 服务、模拟 PostgreSQL 连接及模拟模型响应；没有进行现场数据源或在线模型的验收。实际连通性可用 `sources --check` 检查。
