# 单项目多数据源配置引导 Plan

日期：2026-10-11

## 已确认范围

- 沿用命令行和 Windows 启动菜单，不增加 Web 服务或前端。
- 一个 IRO_agent 实例只管理一个项目；该项目可配置多个代码目录、PostgreSQL 数据库、日志目录和只读 HTTP GET 接口。
- 新项目必须完成配置向导，才能执行认知初始化、查询、故障诊断和网关启动。
- 不自动切换项目，不增加数据库驱动，不修改被诊断项目，不部署或推送。

## 实施步骤

1. **配置结构与强制检查**
   - 增加带唯一来源 ID、用途说明的多源配置，保留旧配置的向导导入入口。
   - 移除新环境对 TASK-013 路径、示例文件及默认业务数据库的隐式依赖。
   - 保存完成标记及配置指纹；项目或数据源配置被直接更改后，要求重新完成向导。
   - 未完成时在实际工作入口阻断；帮助、配置查看、自检、来源检查及离线测试（pytest）仍可用于维护。
2. **分步配置向导**
   - 新增 `setup`：确认项目 → 逐个添加/移除来源 → 模型及可选飞书凭据 → 校验 → 脱敏摘要 → 确认保存。
   - 每类来源支持重复添加，也可明确跳过；至少配置一个来源。
   - Windows 路径自动规范化；凭据支持环境变量，密码输入不回显；中断/取消不覆盖原配置，成功时原子保存。
   - 已有配置保留并导入，新数据源可通过重新运行向导追加。
3. **统一多源读取**
   - 事实问答与 Investigation Harness 使用同一来源读取适配层。
   - 代码、日志可跨已配置来源检索；数据库查询按来源分别执行，结果注明来源，不做跨库 SQL JOIN。
   - 新增来源清单工具，模型可发现来源、用途并指定来源 ID；失败来源返回观测缺口，不能当作无异常。
   - HTTP 仅访问已登记的精确端点，使用 GET，不跟随重定向，不启用浏览器、表单登录或写请求。
   - 项目认知扫描覆盖已配置代码来源和数据库，知识及证据保留来源信息，避免同名文件/表混淆。
4. **Windows 入口与使用说明**
   - 启动菜单加入配置向导和来源查看；未完成配置时引导先完成流程。
   - 修正示例 JSON，补充首次启动、迁移、追加来源、环境变量及查询示例。
5. **验证、整体 review 与修复**
   - 先记录现有测试基线。
   - 验证首次启动阻断、多源实际读取、指定来源、未知来源、部分不可用、凭据脱敏、取消保护、配置变更失效及 HTTP 只读边界。
   - 运行完整自动化测试；整体检查配置 → CLI → 普通问答/故障调查 → 知识扫描链路，并修复发现的问题。
   - 交付代码、使用方法及测试/review 记录；不触碰用户现有 `config.json` 和现场数据。

## 验收标准

- 全新目录运行正常业务命令时，明确提示先完成 `setup`，退出码非零，且不访问现场来源或调用模型。
- 一次向导可以保存同项目下每类多个来源，后续运行无需机械编辑 JSON；重跑可追加和删除来源。
- 未配置某类来源时不访问默认本地数据库或旧项目目录。
- 同名文件、同名表在结果中可按来源区分；一处失败不抹去其他来源结果，同时显式报告失败。
- HTTP/SQL/文件访问继续受只读边界约束；配置摘要及模型来源清单不泄露凭据。
- 测试通过，review 问题修复，已知限制如实记录；本地模拟测试不冒充现场连通性验收。
