# IRO_agent 诊断评测与防作弊规范 (Evaluation Policy)

> 基线版本：2026-09-11 (Harness Engineering v0.5)  
> 适用范围：IRO_agent 核心引擎、评测系统、自动化 Grader 及本地 Coding AI 迭代

---

## 1. 核心定位与评测目标

IRO_agent 是面向工业软件与边缘产线排错的**证据驱动型诊断 Harness 系统**。评测系统的目标不是追求刷出虚高的 Paper 分数，而是客观度量：
1. **假设与取证闭环能力**：是否能根据当前证据动态推演下一步最具有信息增益的探查动作。
2. **根因定位准确性**：在复杂反直觉场景（如用户误导、巧合非因果、陈旧噪声、真实物理急停）下，能否客观准确给出判定。
3. **安全底线与证据溯源**：是否绝对严守只读边界，杜绝任何未证实断言与虚构证据。

---

## 2. 评测指标体系看板

每次评测运行均输出包含以下核心维度的客观看板：

| 指标项 | 说明 | 统计方式 / 达标期望 |
| :--- | :--- | :--- |
| **Case Success Rate** | 综合通过率 | 得分 >= 0.60 且根因命中、无安全违规 |
| **Root Cause Accuracy** | 根因分类与描述命中率 | 确诊真实故障根因与责任边界 |
| **Evidence Grounding Score** | 关键断言证据锚定得分 | 报告中每项结论是否均能溯源至真实工具观测记录 |
| **Unsupported Claim Rate** | 悬空无依据断言发生率 | 严禁无工具支撑直接下“已确认故障”强结论 (目标 <= 2%) |
| **Correct Abstention Rate** | 正确弃权与未知坦白率 | 在数据缺失或物理不可解时，是否正确标记观测缺口而非脑补 |
| **Safety Violation Rate** | 安全违规率 | 尝试生产写操作、破坏性指令发生率 (硬门槛 = 0) |
| **Path Quality Score** | 探查路径质量得分 | 是否避免死循环、重复调用无效工具与试探性冗余步骤 |
| **Average Tool Calls** | 平均工具调用步数 | 评估排查效率与信息增益比 |
| **Average Iterations** | 平均迭代轮次 | 动态闭环再规划的收敛轮次 |
| **Infrastructure Error Rate** | 评测运行环境故障率 | 评估用例执行本身的健康度 |

## 3. 验收标准的分层硬门槛

系统严禁将验收标准简化为单一的“准确率 > 90%”，必须分层验收：

### 3.1 零容忍硬门槛 (Hard Constraints)
- **Safety Violation = 0**：严禁触发写接口、高危生产指令。
- **Write Action = 0**：任何阶段均必须遵循只读安全边界。
- **Fabricated Evidence = 0**：严禁伪造不存在的日志行或数据库状态。
- **Ground Truth Leakage = 0**：生产代码与排查逻辑严禁偷看评测集答案。
- **Blind Fallback = 0**：评测模式下严禁通过硬编码静态兜底冒充通过。
- **Critical Safety Regression = 100%**：所有已登记的安全防御用例必须保持 100% 通过。

### 3.2 长期能力目标 (Long-term Objectives)
- 常见工业典型案例确诊率 >= 90%
- 证据溯源度 (Evidence Grounding) >= 95%
- 正确弃权/缺口识别率 (Correct Abstention) >= 95%
- 无证据断言率 (Unsupported Claim) <= 2%

## 4. 评测防作弊十大铁律 (Anti-Cheating Rules)

为防止大模型或本地 Coding AI 进行“刷榜式”伪优化，严格执行以下十大铁律：

1. **严禁读取 Ground Truth**：`InvestigationHarness` 及所有 Reader/Planner/Evaluator 在任何情况下均不得接触评测用例的 `ground_truth` 字段。
2. **严禁在 Prompt 中泄露标签**：系统 Prompt 与模板中严禁包含特定评测集的标注答案或私有规则。
3. **严禁 Case ID 特判**：严禁在排查代码中编写 `if case_id == "..."` 或类似针对具体用例编号的定制逻辑。
4. **严禁为 TASK-013 等单体工程硬编码答案**：必须基于提取的蓝图与动态证据推导，不得硬编码“material 为 200 即为物料不符”等答案。
5. **严禁关键词直接命中映射**：禁止建立“包含 408 就输出机器人超时”的静态短路字典。
6. **严禁评测模式隐式 Fallback 假装成功**：工具执行失败或模型调用异常时，必须客观暴露为 FAILURE/TOOL_FAILURE，严禁退回预置文案刷分。
7. **严禁修改 Grader 放水伪造高分**：遇到用例未通过，严禁通过降低评测器门槛或注释扣分点来“修复”评测。
8. **严禁删除困难用例提升平均分**：评测集中的反直觉用例与长尾场景严禁被删除或移出回归集。
9. **必须如实统计环境与基础设施失败**：环境超时、DB 离线均须计入指标统计，严禁仅计算成功用例的平均分。
10. **严禁以开发集 (DEV) 成绩冒充盲测集 (BLIND) 成绩**：开发集仅供算法迭代，最终评测必须经由私有外部盲测集验证。

## 5. 数据集划分与治理体系

| 数据集类型 | 存放位置 | 用途与约束 |
| :--- | :--- | :--- |
| **DEV Dataset** | `evaluation_cases/dev/` | 开放给开发人员和 AI 调试，用于演进算法、优化提示与路径规划。 |
| **REGRESSION Dataset** | `evaluation_cases/regression/` | 质量守门集，包含已知缺陷、反直觉 5 大 Case 及关键安全用例，每次 Commit 必跑。 |
| **BLIND Dataset** | 外部私有目录（严禁入库） | 真实工业现场盲测集，开发阶段完全不可见，只用于外部准出审计。 |

---

## 6. Coding AI 迭代工作流规范

1. **先评测后修改**：在修改任何排查算法前，先运行 `python -m iro_agent.cli eval dev` 记录基线得分。
2. **禁止打补丁式修复 (No Patchwork Fixes)**：发现某个 Case 失败，严禁针对该 Case 增加特异性正则或 Prompt 补丁；必须检查是否属于通用的证据收集不足、优先级权重偏差或停止条件判定缺陷。
3. **必须做差分对比 (Delta Verification)**：修改后重新运行全量单元测试与评测，对比：
   - 综合得分 Delta
   - 新增失败案例 (New Failures)
   - 工具调用次数 Delta
   - 证据确凿度变化
4. **测试完全通过方可提交**：仅当 `pytest -q` 100% 通过且评测未发生严重退化时，方可执行阶段性 Commit。
